# 0.2.6 文件夹剪贴板修复候选

本次修复针对 Windows 上“远端复制文件夹，本地资源管理器粘贴失败”。
这是待实机验收的候选版本，不表示已经在目标远端验证成功。

## 已定位并修正

- 写入 CF_HDROP 后，使用会清空剪贴板的接口写 Preferred DropEffect，导致刚写入的文件列表丢失。现改为追加格式；在独立 WindowStation 中使用真实 Windows 剪贴板验证，不触碰用户交互桌面的剪贴板。
- 流式文件客户端缺少 FILECLIP_NO_FILE_PATHS 协商标志。
- 将 CF_HDROP、FileNameW 或 FileContents 当成 FileGroupDescriptorW 请求。这些格式不可互换，现只请求真正的描述符列表。
- 初始格式注册将 FileContents 占用了 IronRDP 用于 Preferred DropEffect 的 ID。
- 小文件首次 RANGE、SIZE 探测后的 RANGE 请求超过文件大小，被当前 IronRDP 拒绝。
- 目录下载结束发布叶子文件，丢失复制的顶层文件夹语义；空目录没有任何流完成事件，永远不发布。
- 大目录的请求队列满时静默丢请求。现保留待发队列，逐个推进文件流；完成通知和最终发布使用可靠发送。
- 失败或提前 EOF 的文件仍作为成功目录发布。现失败批次不发布不完整目录。
- 移除错误的手工 LockData 注入，使用 IronRDP 本身对流式文件提供的锁定处理。
- 旧诊断的消息编号和网络层级解析错误。现 TX 记录封装前 PDU；RX 只解析去掉 SVC 头的 FIRST 分片，明确标为 RX-FIRST-CHUNK，不冒充完整重组。日志不再输出剪贴板正文或文件内容十六进制。

## 自动验证

- 后端完整测试：62 项，包括 11 项新剪贴板集成回归和 1 项真实 Win32 剪贴板回归。
- 前端测试：32 项；另执行 TypeScript 类型检查、Vite 构建。
- 多文件回归使用 70 个文件、4 格请求队列、32 格状态队列，模拟消费端延迟。
- 发布构建、插件打包和解包后 sidecar 启动握手通过；包内程序与 `bin/windows-x64/` 中同步后的程序 SHA-256 一致。插件包哈希与 `.artifact.json` 一致。

## 实机验收

1. DBX 安装 `dist/io.github.caizong10.rdp-0.2.6-windows-x64.dbxp`，断开旧连接后重新连接，使新能力协商生效。
2. 在远端复制包含中文名、多级子目录、普通小文件和空目录的文件夹。
3. 等待后台下载完成，在本地资源管理器使用 Ctrl+V 和右键粘贴各验证一次；核对目录层级、文件数量与内容。
4. 再测试超过 64 个文件的目录，以及文件、文字之间交替复制。
5. 如失败，保留插件数据目录中的诊断日志；记录复制时刻、粘贴时刻、文件数量和是否出现进度。不要提供密码或文件正文。

## 尚未覆盖的体验与风险

当前实现仍然先下载到临时目录，再发布本地 CF_HDROP；不是完整的 OLE IDataObject/IStream 按需虚拟文件桥接。下载未完成时立刻粘贴，旧的延迟占位仍可能返回空列表，需等待下载完成后重试。不能据此声称大目录已经达到 mstsc 的即时粘贴体验。

快速连续复制、复制期间切换剪贴板内容、多连接同时竞争系统剪贴板、远端中断或长期不响应仍需要实机验收；本轮未重写这些状态管理。旧版基于时间的回声抑制及重试机制仍保留，可能影响快速连续操作。

原有 0.2.3、0.2.5 包保留；本轮不提交 Git、不发布到远端仓库。
