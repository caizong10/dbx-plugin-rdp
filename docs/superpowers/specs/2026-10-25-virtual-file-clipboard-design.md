# 虚拟文件剪贴板与按需传输设计

## 目标

远端复制文件夹后，本地第一次点击粘贴就应开始实际传输，不再先向资源管理器返回空的 `CF_HDROP`。大文件应边读取边写入目标位置，并尽可能由 Windows 资源管理器显示原生复制进度。目标体验接近 mstsc，但不承诺完全复刻 mstsc 的内部实现。

## 现状与根因

当前流程是：远端 `FileGroupDescriptorW` 到达后，插件启动后台下载；同时向本地剪贴板放置延迟 `CF_HDROP`。资源管理器首次请求 `CF_HDROP` 时，如果后台下载还没完成，剪贴板所有者立即返回空列表。日志已证明大目录通常需要约 5--7 秒下载，首次粘贴因此无效，第二次粘贴才读取到已发布的真实路径。

## 设计

Windows 路径新增一个虚拟文件剪贴板提供者。它持有远端文件描述符和一个 COM `IDataObject`，公开 `CFSTR_FILEDESCRIPTORW` 元数据以及延迟 `CFSTR_FILECONTENTS` 数据。资源管理器第一次粘贴时，通过 `IDataObject::GetData` 请求具体文件的 `IStream`；流的读取操作由会话层转成 CLIPRDR `FileContentsRequest`，按有限大小分块取得远端数据，再返回给资源管理器。目录结构继续由描述符中的相对路径表示。

当前的临时目录 + `CF_HDROP` 流程保留为兼容回退：COM 对象注册失败、资源管理器不接受虚拟对象、远端流发生不可恢复错误时，回退流程可以继续完成复制。回退不得再在首次粘贴时写空列表；应等待下载完成后再发布真实 `CF_HDROP`，或明确报告失败。

## 组件边界

- `clip_virtual.rs`：Windows COM 数据对象、格式枚举、`IStream` 适配器和生命周期管理；不直接操作 RDP socket。
- `clip_transfer.rs`：为虚拟流提供同步的按位置读取接口；一个请求最多读取 1 MiB，保持现有大小、范围和锁校验。
- `rdp.rs`：把资源管理器的流读取转换为 session-thread 请求，接收 CLIPRDR 响应并唤醒对应流；管理远端剪贴板 generation，避免旧复制污染新复制。
- `clip_owner.rs`：保留窗口线程和剪贴板所有权，但新增虚拟对象注册/撤销入口；不再在虚拟对象可用时先注册空 `CF_HDROP`。

## 可见行为

1. 收到远端描述符后，剪贴板立即包含文件名、目录结构和大小元数据，资源管理器可以启用粘贴。
2. 第一次粘贴触发第一个文件的按需读取；读取期间显示资源管理器自己的复制进度（若该版本资源管理器选择显示）。
3. 多文件按资源管理器请求顺序读取，不预先下载整个目录；支持取消，取消后释放流和远端请求。
4. 空目录保留在描述符中；不再依赖“文件流完成”触发目录发布。
5. 旧版本或不支持虚拟文件的场景走真实路径回退。

## 错误与安全

- 每个虚拟剪贴板 generation 都有唯一 ID；旧 generation 的响应不得写入新流。
- 流读取超时、远端错误、范围越界返回明确的 COM 流错误；不能返回伪造的零字节成功。
- COM 对象不保存凭据，不把文件正文写入日志；日志只记录请求索引、位置、长度和错误。
- 关闭 RDP session 时撤销剪贴板对象，释放等待中的请求和事件。

## 分阶段交付

第一阶段只做 Windows 原型：在私有 WindowStation 中验证 Explorer 可读取虚拟文件对象、目录元数据和一个分块流；不接入 RDP。

第二阶段接入真实 `FileContentsRequest/Response`，先支持单文件和小目录，再加入取消、generation 和回退。

第三阶段打包、实机测试，并比较首次粘贴响应时间、总传输时间、失败行为和回退行为。

## 验收标准

- 第一次点击粘贴不再得到空文件列表。
- 10 MB 以上文件可以通过一次粘贴完成，读取至少分成两个流块。
- 多级目录和空目录结构保持。
- 远端中断时资源管理器收到失败而不是假成功；随后可以复制新的文件夹。
- 当前 0.2.6 回退包仍可安装，主流程测试和 Windows 剪贴板回归测试继续通过。
